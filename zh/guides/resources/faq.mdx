<AccordionGroup>
  <Accordion title="Starrise 是什么？提供哪些核心能力？">
    Starrise 是一个企业级 AI API 聚合平台。通过一个 API Key 和一个 Base URL，即可统一调用 Claude、GPT/OpenAI、Gemini、DeepSeek、Qwen、GLM、Kimi、Grok、Doubao 等主流模型，并集中管理用量、账单与调用日志。

    核心能力包括：统一接入、智能路由与故障切换、用量与成本透明、企业级密钥与权限管理，以及阿联酋本地团队 24/7 支持。

    可在本文档的[模型列表](/zh/guides/system-api/models-list)或 Starrise 模型市场中查看可用模型。模型名称需与市场中的名称完全一致，否则调用会失败。
  </Accordion>

  <Accordion title="计费方式是怎样的？与官方 API 相比价格如何？">
    采用预充值、按实际用量扣费：先充值，调用时按各模型的计价标准从余额扣除，不收月费，用多少付多少。对话模型按 Token 计费，图片和视频生成模型按次计费。

    平台展示的是各模型官方标价，可直接对比；不同模型价格不同，以模型市场或报价单为准。企业客户可联系我们获取折扣报价。多家模型统一充值与账单、切换模型无需重新对接，也能节省管理与切换成本。

    前往[充值页面](https://ai.alad.com/console/topup)添加额度。计费说明见[充值付款](/zh/guides/resources/payment)。
  </Accordion>

  <Accordion title="积分用完了怎么办？">
    API 调用会返回 `402 Payment Required` 错误。前往[控制台](https://ai.alad.com/console/topup)充值后即可恢复使用。建议开启余额预警，避免调用中断；企业账户可将阈值设为月均消耗的 20%。
  </Accordion>

  <Accordion title="会存储我的请求内容吗？数据会被用于训练吗？">
    不会存储请求内容：提示词、模型回复及上传的文件和图片仅在请求处理期间保存在内存中，处理完成后即释放，不写入磁盘或数据库，平台也不提供记录完整请求内容的开关。

    平台仅保留调用元数据（模型、token 数、延迟、线路、请求 ID）、账单记录和管理审计记录；来源 IP 和错误信息默认不记录，如开启会先脱敏。

    数据的训练用途、驻留和删除机制以具体线路、供应商政策及合同条款为准。企业客户上线前应确认适用方案并完成内部合规评估。
  </Accordion>

  <Accordion title="账户和 API 密钥有哪些安全设置？">
    每个 API 密钥可单独设置有效期、消费上限和 IP 白名单，并在界面中脱敏显示，不会以明文出现在日志中。可通过子账户隔离内部团队：主账户可查看自身及子账户数据，子账户仅能查看自身数据。账户支持双因素认证、通行密钥和企业单点登录（SSO）。
  </Accordion>

  <Accordion title="如何接入？API 地址是什么？">
    在 [ai.alad.com](https://ai.alad.com) 注册并登录后，在[控制台](https://ai.alad.com/console/token)创建 API Key，把原有 OpenAI 调用中的 Base URL 和 API Key 替换为 Starrise 的即可。对话模型兼容 OpenAI 格式，无需大幅改动代码，将 `base_url` 设为 `https://ai.alad.com/v1`。

    常用接口地址形如 `https://ai.alad.com/v1/chat/completions`，具体以控制台为准。模型名称需与 Starrise 模型市场中的名称完全一致，否则调用会失败。

    第一次调用可参考[快速开始](/zh/quickstart)。
  </Accordion>

  <Accordion title="和直接对接模型厂商相比，有什么区别？">
    企业只需对接一次，即可调用多家主流模型，并在同一控制台统一管理密钥、权限、用量与账单，无需与每家厂商分别签约、对接和对账，也不会被单一厂商绑定。

    与一般聚合平台相比，Starrise 的差异在于：阿联酋本地团队 24/7 支持；同一接口兼顾国际与国产模型；支持对公转账、多币种付款并开具正式发票；企业客户可按使用模型和用量获取折扣报价。
  </Accordion>

  <Accordion title="如何获得技术支持？">
    Starrise 由阿联酋本地团队提供 24/7 技术支持，可通过控制台、邮箱或 WhatsApp 联系我们。排查故障请提供请求 ID、时间、模型名、接口路径、HTTP 状态码、完整错误信息、客户端及版本、相关配置（隐藏 API Key）和可复现步骤。请勿在工单、群聊或截图中公开完整 API Key、密码或钱包私钥。
  </Accordion>

  <Accordion title="企业客户如何充值、付款以及开票？">
    企业客户由运营团队人工充值，款项通常 1 个工作日内到账。平台支持余额预警，建议将阈值设为月均消耗的 20%，触发后及时充值，避免接口调用中断。

    付款支持对公银行转账，可提供 USD、HKD、AED 等多币种结算；具体收款账户与付款要求会随发票一并提供。请在付款前与我方团队确认，切勿使用非官方渠道提供的账户信息。

    自助充值可使用信用卡，见[充值页面](https://ai.alad.com/console/topup)和[充值付款](/zh/guides/resources/payment)。
  </Accordion>

  <Accordion title="如何创建和管理 API Key？">
    在控制台[Token 管理](https://ai.alad.com/console/token)页面可创建、查看和禁用 Key，并为不同项目、团队或客户设置独立分组、配额与权限。每个 Key 可单独设置有效期、消费上限和 IP 白名单，界面中脱敏显示，不会以明文出现在日志中。账户支持子账户隔离、双因素认证、通行密钥和企业单点登录（SSO）。
  </Accordion>

  <Accordion title="如何查看消费与用量明细？">
    在控制台查看：仪表盘显示消费总额，调用日志按模型展示明细与用量趋势，账单页记录充值。企业还可通过多 Key、多分组、配额、权限和余额预警管理用量与成本。建议为不同环境和团队分配独立 Key，并定期导出调用明细核对企业账单。
  </Accordion>

  <Accordion title="是否提供测试额度？">
    可以为有意向的企业或开发团队开通测试额度。申请测试请说明使用场景、预计调用量、目标模型、预计并发和希望测试的时间。
  </Accordion>

  <Accordion title="如何接入 Claude 桌面端、Codex 等客户端？">
    可通过 [CC Switch](/zh/guides/usecases/use-anyfast-in-cc-switch) 等工具将 Claude 桌面端、Codex 等应用的请求路由到 Starrise，也可在 Claude 桌面端开发者模式下直接配置第三方 API。

    对接步骤见：

    * [CC Switch](/zh/guides/usecases/use-anyfast-in-cc-switch)
    * [Codex](/zh/guides/usecases/use-anyfast-in-codex)
    * [Claude Code](/zh/guides/usecases/use-anyfast-in-claude-code)
  </Accordion>
</AccordionGroup>
